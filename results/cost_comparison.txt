COST COMPARISON: PRUNED vs DENSE
============================================================

We measure cost as forward-pass FLOPs (multiply-accumulate
operations) counting ONLY active (non-zero-mask) connections.
This is NOT a dense-times-zero shortcut — our sparse_forward_flops
function counts mask.sum() per layer, so a pruned connection
genuinely contributes zero FLOPs to the count.

However, our actual forward pass still uses dense matmul (NumPy
does not have sparse BLAS). The FLOP count is a *theoretical*
measure of work that a sparse-aware kernel WOULD save. In a
production system (e.g. AQUA), you would use a sparse GEMM
kernel or a compressed sparse row (CSR) representation to
realise these savings on real hardware.
